# NPC Bot Base Structure — v2 (2026-10-09)

*The revamped base structure for NPC bots: what an NPC subagent is made of, how
it is built, isolated, and verified. Companion to `bot/npc-maker/README.md`
(the operational doctrine) and the landscape survey
(`research-ai-npc-agents-landscape-2026-10.md`).*

## Why a revamp

The landscape survey (2026-10-08) found no public product, project, or play
report running this pattern — one persistent agent per NPC (own memory, own
voice) orchestrated by a separate GM agent, across sessions, live in a VTT.
Every ingredient exists separately (Familiar, Chronicle Keeper, Corvus, dmcp)
and the per-NPC persistent voice is the unclaimed part. The v2 revamp keeps
that shape and fixes what live play surfaced.

The 2026-10-09 audit found three real defects in v1, all verified live:

1. **Context leak.** Turns launched from a context-bearing directory (e.g. the
   repo) loaded that directory's project context — `AGENTS.md`, git status,
   recent commit subjects — into the character's system prompt. Four of six
   bots carried it in a stored prompt. Operator context inside a character
   prompt is a knowledge-boundary failure.
2. **Tool surface.** Bot profiles carried the stock ~20-tool set (web,
   terminal, file, browser, delegation, …). An NPC needs none of it, and the
   schemas cost roughly 40k characters of prompt on every turn.
3. **Verification gaps.** No safe model re-pin after a swap (stale session
   pins that a config readback cannot reveal) and no live check in the maker
   (readback only).

## What an NPC bot is (anatomy v2)

- **Campaign side** (source of truth, gitignored):
  `campaigns/<id>/npcs/<slug>/` — `dossier.md` (the answered Literary Build
  sheet), `soul.md` (the persona; becomes the profile's `SOUL.md`), and
  `bot.yaml` (title / description / model / provider).
- **Profile side** (generated by the maker — never hand-edited):
  `~/.hermes/profiles/npc-<slug>/` — `SOUL.md`, `dossier.md`, the canonical
  `Bot Chat` session, model config, the provider key in `.env`, and
  `workspace/` (the pinned neutral working directory).
- **The rail:** the GM reaches a bot with Bot Mode's `message_agent`; the reply
  returns as the delivery process result and/or the bot's own `message_agent`
  delivery into the GM chat. Relayed lines carry the bot-voice marker (`^"…"`).

## The five pillars

### 1. Isolation is the profile — unchanged

One profile per NPC; its own SOUL, sessions, memory, credentials. Knowledge
boundaries are a filesystem fact, not a promise. Dormant bots cost $0.

### 2. Context hygiene — new

- `terminal.cwd` is pinned at build time to the profile's own empty
  `workspace/` directory. Every cwd consumer — context-file discovery, the
  workspace snapshot, the tools — resolves through it.
- Effect: a bot's prompt contains its persona and the platform's protocols,
  nothing else, no matter where a turn was launched from.
- Verified: a turn deliberately launched from the repo rebuilt the prompt with
  no Project Context section; the stored-prompt audit across all six bots
  shows zero leaked rows.

### 3. Tools policy — new

- Exactly one toolset stays enabled: `memory`. Every other toolset is
  disabled at the profile (`hermes tools disable … --platform cli`).
- `message_agent` is **not a toolset** — Bot Mode injects it at turn time for
  managed Bot Chat sessions, so it survives the lockdown (verified live).
- Why: a hard capability boundary (an NPC cannot browse, run, or write files)
  plus prompt economy — the tools payload fell from ~40k to ~5.7k characters
  and the full prompt from ~66k to ~18k (a 73% cut).
- A deliberate exception for a future NPC: run the maker with
  `NPC_KEEP_TOOLSETS="memory <extra>"`, or enable the toolset and note the
  decision here.

### 4. Memory — three layers, settled

1. **The canonical Bot Chat** — the forever-chat; `/new` compacts instead of
   forking by design. The operative memory of play.
2. **Built-in `MEMORY.md`** per profile — the memory toolset is the one tool
   left enabled; the maker caps it at 1000 chars so a bot can keep compact,
   durable notes.
3. **Not default — a per-NPC TencentDB store** for semantic recall when a long
   arc genuinely demands it. Each store costs a gateway process, and dormant
   bots cost $0 by design, so this is enabled per active NPC, never for the
   roster. Mechanism: `~/.hermes/scripts/memory-gateway-launch.sh <profile>`.

### 5. Verification & model lifecycle — new

- `make-npc.sh --smoke` — one delivery-style live turn into the Bot Chat,
  printing the reply and the `agent.log` turn line as evidence.
- `repin-model.sh <slug>` — safe session re-pin after a model swap: timestamped
  backup of `state.db`, targeted update of the pins (model + billing; base URL
  from the GM profile's known-good same-stack session), readback, then a live
  resumed turn whose `agent.log` line proves the effective model. `--offline`
  skips the live turn (readback only — not proof).
- The maker's verify block prints model, provider, env key names, Bot Mode
  marker, `terminal.cwd`, enabled toolsets, memory limits, persona/dossier
  presence, and the Bot Chat row — and `--verify-only` is the read-only drift
  check.
- Evidence of record for deliveries: the calling profile's
  `logs/process-results/proc_*.json` plus the bot's own chat.

## Delivery-rail boundaries (learned live, 2026-10-09)

- A delivery into a Bot Chat that has a **live owner** is queued for that
  owner. A delivery while a **headless turn** holds the chat is refused
  (`target_busy`, "open on another surface") and the sender is told — not
  queued. Retry once the surface clears; verified clean.
- Don't test NPC→GM replies while holding the GM's Bot Chat with a synchronous
  headless turn — the reply will bounce by design. Fire the send, let the turn
  end, then let the reply land (or have the NPC retry).
- Headless GM turns: cap with `--max-turns` and instruct "end immediately" for
  checks. An unconstrained GM turn will investigate a delivery anomaly at
  length — correct instincts, real cost.

## Ops cheat-sheet

```bash
# build or refresh (idempotent; keeps the profile's SOUL if the campaign copy is absent)
bash bot/npc-maker/make-npc.sh delta-green-convergence <slug>

# read-only drift check
bash bot/npc-maker/make-npc.sh delta-green-convergence <slug> --verify-only

# drift check + one live voice turn into the Bot Chat
bash bot/npc-maker/make-npc.sh delta-green-convergence <slug> --verify-only --smoke

# model swap: config → bot.yaml → session pins
hermes -p npc-<slug> config set model.default <raw-model-id>
#   (edit the campaign bot.yaml model:/provider: to match)
bash bot/npc-maker/repin-model.sh <slug>
```

## Verified record — 2026-10-09

- All six bots refreshed to v2: tools = `memory` only; `terminal.cwd` pinned;
  memory limit 1000; stored prompts clean of project context.
- One live smoke turn per bot (~3–7 s turns): Billy, Dan, Frank, Jane, Angel,
  Derringer — every reply in voice on `deepseek-flash`, each with its
  `agent.log` evidence line.
- Full GM → NPC → GM round trip through the rail: brief delivered (exit 0), an
  in-character reply composed and delivered into the GM chat, receipt
  acknowledged; the retry-after-surface-clears path also exercised live.
- Prompt economy: full NPC system prompt ~66k → ~18k characters; tools payload
  ~40k → ~5.7k.
